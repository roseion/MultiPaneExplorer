# v1.6.0（对比文档 P0）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 补齐对比文档 P0 五项：撤销/重做、回收站视图与还原、大图标/列表视图+图片缩略图、面包屑地址栏、F2 内联重命名。

**Architecture:** 核心能力（回收站 $I/$R 直解、传输明细、撤销栈）全部落在 FileOps.Core 配 xUnit；App 层只做接入。回收站视图复用现有窗格（`CurrentPath = "recyclebin:"` 特殊值）；视图模式用同一 ListView 的 Style 触发器切换 ItemsPanel/ItemTemplate/容器模板；面包屑与内联重命名在 ExplorerPane 内完成。

**Tech Stack:** .NET 8 WPF、CommunityToolkit.Mvvm、xUnit。零新 NuGet 依赖。

**Spec:** `docs/Win11资源管理器功能对比分析.md` §3 P0 清单（v1.5.0 tag 已被 Fluent 主题占用，本版按序号为 v1.6.0）。

## Global Constraints

- 每个任务独立 commit，交付前 `dotnet test MultiPaneExplorer.slnx` 全绿（当前基线 56/56）。
- 核心逻辑进 FileOps.Core 并配单测；UI 手动验收。

- 中文注释与提交信息；不动 .gitignore、不加第三方 UI 库。

**Interfaces（后续任务依赖）:**
```csharp
public sealed record RecycleBinEntry(string OriginalPath, string OriginalName, bool IsDirectory,
    long SizeBytes, DateTime DeletedTime, string ItemPath, string InfoPath); // ItemPath=$R，InfoPath=$I

public interface IRecycleBinService
{
    Task<IReadOnlyList<RecycleBinEntry>> EnumerateAsync(CancellationToken ct = default);
    Task<IReadOnlyList<string>> RestoreAsync(IEnumerable<RecycleBinEntry> entries, CancellationToken ct = default);
    Task<int> DeletePermanentlyAsync(IEnumerable<RecycleBinEntry> entries, CancellationToken ct = default);
    Task<int> EmptyAsync(CancellationToken ct = default);
    IReadOnlyList<string> Snapshot();                                   // 现存 $I 路径
    Task<IReadOnlyList<RecycleBinEntry>> DiffAsync(IReadOnlyList<string> before, CancellationToken ct = default);
}
```

**要点:** $I v2 布局 = `[0..4)` 版本号、`[8..16)` 大小、`[16..24)` FILETIME、`[24..32)` 名称字符数、`[32..)` UTF-16 名称；v1 = 名称固定 520 字节。还原目标被占用时走 `FileOperationService.GetAvailablePath`（internal 同程序集可用）；父目录缺失则创建。枚举用 `EnumerationOptions { AttributesToSkip = FileAttributes.None, IgnoreInaccessible = true }`（$I 为隐藏系统文件）。盘根 = 各固定盘 `$Recycle.Bin\{WindowsIdentity.GetCurrent().User}`。

- [ ] 失败测试：`ParseInfo_V2/V1`（手工构造字节）、`Restore_MovesBackAndDeletesInfo`、`Restore_WhenTargetOccupied_RenamesWithSuffix`、`DeletePermanently_RemovesPair`（用临时目录手工摆放 $I/$R 对，不触真实回收站）

### Task 3: 撤销/重做服务（FileOps.Core）

**Files:**
- Create: `src/FileOps.Core/UndoRedoService.cs`（含 IUndoableOperation 与 4 种操作记录）
- Test: `tests/FileOps.Core.Tests/UndoRedoTests.cs`

**Interfaces:**
```csharp
public interface IUndoableOperation
{
    string Description { get; } bool CanUndo { get; } bool CanRedo { get; }
    Task UndoAsync(CancellationToken ct = default); Task RedoAsync(CancellationToken ct = default);
}
public sealed class UndoRedoService
{
    bool CanUndo/CanRedo { get; } string? UndoDescription/RedoDescription { get; }
    void Push(IUndoableOperation op);              // 清空 redo 栈并触发 Changed
    Task<string> UndoAsync(ct); Task<string> RedoAsync(ct);  // 返回描述；空栈抛 InvalidOperationException
    event Action? Changed;
}
public sealed class TransferOperation : IUndoableOperation // (ops, items, targetDir, move, verb)
// move=false：Undo=把 destinations 删进回收站；Redo=按 items.Source 重新 CopyIntoAsync
// move=true ：Undo=把 destinations 移回各 Source 父目录；Redo=重新 MoveIntoAsync
public sealed class DeleteOperation      // (ops, bin, originalPaths, binEntries) Undo=还原；Redo=再删进回收站
public sealed class RenameOperation      // (ops, oldPath, newPath)
public sealed class CreateOperation      // (ops, path, isDirectory) Undo=永久删除（目录须为空）；Redo=重建
```
Undo 成功后该操作移入 redo 栈（`CanRedo=false` 时丢弃）；Undo 执行异常时操作留在撤销栈并向上抛。

- [ ] 失败测试：复制→撤销目标消失→重做恢复；移动→往返；重命名→往返；删回收站→撤销内容回到原路径→重做再删；Replace 传输 CanUndo=false；Push 清空 redo
- [ ] 实现 → 测试过 → commit `feat(core): 撤销/重做服务与四类操作记录`
